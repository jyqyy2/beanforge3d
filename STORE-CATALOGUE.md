# V1 catalogue and next data phases

The Supabase dashboard labels the user-designated staging project's main branch `PRODUCTION`. Confirm that this project is isolated from real customer traffic before further rollout.

The storefront reads active categories, products, colours and variants through Supabase's anonymous REST API and RLS when `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are configured. Without those variables, local development uses five bundled product records. A configured request failure shows an error rather than silently selling stale products. Known product slugs retain bundled imagery; adding an arbitrary database row alone does not enable a new checkout type or image.

The board-length/layout and add-on price schedules remain server-owned in the checkout function; the variants control product/colour availability and base-price approval. The updated commerce-checkout function was deployed to that project on November 5, 2026. Read-only remote quotes returned S$4.90 for a one-character Keycap Studio board and S$9.90 for a 2x1 purple Halloween board. The configured local `/shop` showed five products and both studio links. A fresh end-to-end Stripe sandbox checkout remains to verify before live payments. Do not paste a service-role key or Stripe secret into Vite variables.

For future inventory, first decide whether stock is tracked per variant, per assembled board, or per shared component (switches/keycaps), whether made-to-order items can oversell, and how reservations expire on abandoned Stripe sessions. A reviewed migration should add nonnegative stock ledger/reservations and fulfilment events, constrain changes to a server role, and update available-to-sell atomically at checkout. A client-side quantity field is not inventory control.

For digital STL products, decide licence tiers, allowed uses, file versions, refund policy and tax/shipping treatment. Use private object storage, explicit licence/version records and order entitlements granted only after a verified paid webhook; issue short-lived download URLs server-side. Keep digital and physical checkout/shipping distinct. Admin management should use authenticated staff identities, least-privilege RLS and an audited change log, not an anonymous browser write policy. These operational tables and workflows are intentionally not included in the Studio catalogue migration.
